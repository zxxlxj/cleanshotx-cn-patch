# 开发与维护

面向想改词条、适配新版本、或排查汉化失效的人。安装使用请看根目录的 [README](../README.md)。

## 数据流：一张词条表，三处消费

```
src/translations.txt          ← 唯一数据源，人工维护，格式「英文<TAB>中文」
        │
        │  scripts/gen-strings.py
        ├──────────────► src/GeneratedCNTable.h        （编译进 dylib 的运行时翻译表）
        └──────────────► build/zh-Hans.lproj/Localizable.strings （系统语言包）
```

两个产物都是**生成物**，不要手改；改 `translations.txt` 后跑一次
`./scripts/install.sh`（或 `scripts/gen-strings.py`）重新生成即可。

`src/GeneratedCNTable.h` 已加入 `.gitignore`，克隆后由构建脚本自动生成。

## 三条翻译通道

CleanShot X 5.0 把设置界面重写成了 SwiftUI，单一手段覆盖不全。
三条通道**共用同一张词条表**，分工如下：

| 通道 | 负责范围 | 实现位置 |
|---|---|---|
| **A 视图遍历** | 侧边栏、窗口标题、AppKit 控件、菜单栏图标菜单 | `CNTranslateMenu` / `CNTranslateView` / `CNTranslateWindow`；挂钩 `NSMenu` 的 `insertItem:atIndex:`、`addItem:`、`setItems:`、`popUpMenuPositioningItem:atLocation:inView:` 与 `NSStatusItem setMenu:` |
| **B 本地化查询拦截** | SwiftUI `Text("字面量")`、`.strings` 资源 | `__DATA,__interpose` 重绑 `NSBundle` 与 `CFBundleCopyLocalizedString(ForLocalization)` |
| **C 渲染层拦截** | SwiftUI 变量文本、快捷键动作名、Markdown 富文本 | 重绑 `CTLineCreateWithAttributedString`、`CTTypesetterCreateWithAttributedString(AndOptions)`、`CTFramesetterCreateWithAttributedString`、`CFAttributedStringCreate`；并在 `NSAttributedString` 的 `drawAtPoint:` / `drawInRect:` / `drawWithRect:options:context:` 绘制点整句替换 |

### 为什么必须有通道 C

SwiftUI 里 `Text("…[链接](url)…")` 这类富文本，**既不经过 `CTLine`，也不经过
`initWithString:attributes:`** —— 只有真正落笔绘制时才拿得到「解析后的完整句子」。
所以在 `drawWithRect:options:context:` 这一层做整句替换，是唯一能覆盖它的位置。

`cn_translatedForDrawing` 在替换整句的同时会保留链接属性：先把非链接属性铺到整条译文，
再逐条 `NSLinkAttributeName` 在译文里定位对应文字并贴回去。

### 通道 C 的死坑：不能 dlsym 取原函数

`__interpose` 生效后，`dlsym(RTLD_NEXT, …)`、`dlsym(RTLD_DEFAULT, …)`、
以及 `dlopen` 句柄上的 `dlsym` **全部会解析回我们自己的替换函数**，
拿「原函数」就会无限递归爆栈。

唯一可靠做法是用**本镜像内的直接引用**：

```c
CNOrigCTLine = (CNCTLineFn)(const void *)CTLineCreateWithAttributedString;
```

编译器给的是链接期绑定的真实地址，**不会被 interpose 改写**。

另一个隐蔽的坑：如果 interpose 条目被 `#ifdef` 包住而宏没定义，
`__DATA,__interpose` 段会少几条，钩子**静默失效**。
排查方法：`otool -l libCleanShotCN.dylib | grep -A3 __interpose` 看段大小
（5 条 = 0x50）。

## 排查：怎么找漏翻项

### 1. 日志总开关（默认关闭）

正常运行**不写任何日志**。需要排查时创建标记文件后重启应用：

```bash
touch /tmp/cleanshot-cn-debug      # 打开全部日志
touch /tmp/cleanshot-cn-ct-dump    # 只开渲染层日志
rm -f  /tmp/cleanshot-cn-debug     # 关闭（重启应用生效）
```

实现：`CNDebugLogEnabled()` 放在 `CNLogLineTo()` 入口，`CNCTLogEnabled()` 复用它。

日志文件：`/tmp/cleanshot-cn-{menu,ui,cf,ct,keys,perm}.log`

### 2. 自动遍历设置页

```bash
touch /tmp/cleanshot-cn-debug /tmp/cleanshot-cn-open-prefs /tmp/cleanshot-cn-cycle
pkill -x "CleanShot X"; open -a "CleanShot X"
```

`open-prefs` 让注入库自动打开设置窗口，`cycle` 让它在启动约 11 秒后
把侧边栏 10 个页面逐一点一遍（每页停 3.5 秒）。遍历进度写在
`/tmp/cleanshot-cn-cycle.log`，格式：

```
CLICK#3	text=[壁纸]	pt=(70,395)
```

**想给每个页面截图**：跟着这个日志走，看到新的 `CLICK#` 行就
`screencapture -x -o -l <窗口ID>` 抓一次。窗口 ID 可以用
`osascript` 或自建工具遍历 `CGWindowListCopyWindowInfo` 拿到。

> ⚠️ 注意先**彻底退出旧实例再清日志**。否则旧实例会在清理之后继续写
> `CLICK#` 行，造成「截图与页面错位一页」的串扰。

### 3. 判读日志

渲染层日志格式：

```
HIT 	[Capture Area]	->	区域捕捉	via=CTLine
MISS	[Some New Label]	->	(未翻译)	via=CTTypesetter
```

`via=` 标明是 CTLine / CTTypesetter / CTTypesetterOpt / CTFramesetter /
CFAttrCreate / NSAttrInit 哪条通道看到的，便于判断该去哪一层补钩子。

**重要**：`MISS` 里混着大量「已经是中文」的条目 —— 因为日志是拿**译文**再查一次表，
自然查不到。只筛「**纯英文 + 像自然语言**」的条目才算真漏翻：

```bash
grep "^MISS" /tmp/cleanshot-cn-ct.log | \
  python3 -c "
import sys, re
for l in sys.stdin:
    s = l.split('\t')[1].strip('[]')
    if re.search(r'[\u4e00-\u9fff]', s): continue
    if re.match(r'^[A-Za-z]', s) and len(s) >= 4: print(s)"
```

### 4. 静态提取（不启动应用）

```bash
python3 scripts/extract-strings.py > /tmp/candidates.txt
```

从 `__TEXT,__cstring` / `__TEXT,__const` 段和 `__TEXT,__text` 指令流
（还原 Swift 内联小字符串，布局为成对 `movabs`，第 16 字节 `0xE0|长度`）
提取候选文案。**噪声很大** —— 会混进 Security、Sentry、Alamofire、FFmpeg
等框架的内部报错文本，必须人工过一遍。

### 5. 覆盖率

```bash
python3 scripts/check-coverage.py
```

把词条表里的每条原文拿去应用包里做字节流子串匹配，报告有多少条真能命中。

> 统计时**必须同时判 UTF-8 / UTF-16-LE / UTF-16-BE 三种编码**：
> clang 会把含非 ASCII 的 Objective-C 字符串常量存成 UTF-16LE，
> 只认 ASCII 的 `strings` 查中文译文永远查不到，会误判成「没编译进去」。

## 运行时拼接的文案

像 `30 秒`、`60 帧/秒`、`800 × 自动（默认）`、`确定要删除 "文件名"？`
这类是运行时拼出来的，无法精确登记，走 `CNDynamicLookup()` 的两组正则：

1. **文本模式**（≤120 字符）：固定前后缀 + 变量，如
   `^Are you sure you want to delete "(.+)"\?$`
2. **数字 + 单位**（≤40 字符，必须含数字）：如 `^(\d+) fps$`

新增这类文案时改 `src/CleanShotCN.m` 里的 `CNDynamicLookup()`。

## 适配新版本

```bash
./scripts/preflight.sh "/Applications/CleanShot X.app"   # 1. 判断能否注入
./scripts/install.sh                                      # 2. 安装
python3 scripts/extract-strings.py > /tmp/c.txt           # 3. 提取新增文案
# 4. 与 src/translations.txt 求差集，补词条
touch /tmp/cleanshot-cn-debug /tmp/cleanshot-cn-cycle     # 5. 开日志 + 自动遍历
pkill -x "CleanShot X"; open -a "CleanShot X"
grep "^MISS" /tmp/cleanshot-cn-ct.log                     # 6. 看渲染层漏翻项
./scripts/install.sh                                      # 7. 补完词条后重装
rm -f /tmp/cleanshot-cn-debug /tmp/cleanshot-cn-cycle     # 8. 收尾
```

如果新版又换了渲染方式，先开日志跑一次，看
`grep '^WINDOW' /tmp/cleanshot-cn-ui.log` 里的视图类名 ——
出现 `SwiftUI.NSHostingView` 说明还是 SwiftUI，AppKit 类名则说明退回了旧结构，
据此决定补哪条通道。

### 版本记录

| 版本 | 设置界面 | 需要的通道 |
|---|---|---|
| 4.7.4 / 4.8.8 | AppKit | A + B |
| 5.0 | SwiftUI | A + B + C |

## 踩坑记录

**1. `codesign --deep` 会失败。**
应用包内的 `Lava / Sparkle / VectorBoolean / AudioLoop` 等 framework 结构不标准，
`codesign --deep` 报 `bundle format is ambiguous` 并中断，
导致主包 `Info.plist` 封签写坏、应用无法启动
（`_LSOpenURLsWithCompletionHandler() failed ... -54`）。

→ `install.sh` / `uninstall.sh` 改为：先单独签注入的动态库，再**不带 `--deep`** 签主包，
且校验失败只提示不中断。原始应用本身也通不过 `codesign --verify`，属既有现象。

**2. 静态分析无法还原菜单和界面结构。**
`strings` + nib 推断菜单项完全不可靠 —— 字符串在 Mach-O 里分散存放，重建不出结构。
最终靠的是注入库的**运行时日志**才拿到真实清单，
比如 `All-In-One`、`Self-Timer`、`Capture Text (OCR)`、`Activate...`
这些光靠猜根本找不到。

**3. `NSAttributedString` 的构造点只能记录、不能翻译。**
属性串往往由多段拼装而成，逐段翻译会让链接文字先变中文，反而破坏整句匹配。
所以 `cn_initWithString:attributes:` 只记录，整句翻译统一放在绘制点。

**4. 定时器驱动的视图遍历要注意重入。**
`NSWindowDidUpdateNotification` 触发非常频繁，遍历前必须判空、
且翻译函数要幂等（已经是译文就跳过），否则会反复写属性导致卡顿。

## 权限：重签名会让授权作废

ad-hoc 签名下，**macOS 的权限记录（TCC）是按 CDHash 认身份的**，不是按包名。
补丁每次改动都要重签名 → CDHash 变 → 旧授权作废：

> 系统设置里的开关**显示是开的**（那是旧身份的记录），
> 但应用按新身份去申请，系统判定「未授权」。

**判定依据**：注入库调用 `CGPreflightScreenCaptureAccess()` 的结果，
写在 `/tmp/cleanshot-cn-perm.log`（需要先开日志总开关）。
这是唯一可靠依据 —— 系统设置里显示的勾会骗人。

**修复步骤**：

1. 完全退出 CleanShot X（退出进程，不是关窗口）
2. `tccutil reset ScreenCapture pl.maketheweb.cleanshotx`
   （或系统设置里点「−」移除，只拨开关无效）
3. 重新打开应用并允许
4. **再退出重开一次** —— macOS 对屏幕录制权限要求重启应用才生效，这步最容易漏

`install.sh` 会在签名前后比对 CDHash，变化时打印醒目告警和上述步骤。

> 实测：相同输入重复签名，CDHash 完全一致（确定性）。
> 所以**只要不改 `src/CleanShotCN.m`，授权一次就能长期有效**。
